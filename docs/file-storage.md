# Файловое хранилище (Nextcloud)

Аналог Google Drive / Яндекс.Диск: веб-интерфейс, синхронизация папок на ПК (Nextcloud Desktop), мобильные приложения (iOS/Android), общие папки и ссылки, WebDAV.

## Запуск

```bash
docker compose --profile storage up -d
```

Поднимаются сервисы **nextcloud** и **nextcloud_db** (MariaDB). Используется общий **redis** из homelab для кеша/блокировок.

Первый запуск: подождите 1–2 минуты, пока MariaDB пройдёт healthcheck и Nextcloud выполнит установку.

## Доступ

- **Локально:** http://localhost:18082 (порт задаётся `NEXTCLOUD_PORT` в `.env`, по умолчанию 18082).
- **Из сети / снаружи:** см. раздел «Доступ извне».

При первом заходе в веб-интерфейс мастер установки уже не показывается — учётная запись админа создаётся через переменные окружения (см. ниже). Войдите логином и паролем из `NEXTCLOUD_ADMIN_USER` и `NEXTCLOUD_ADMIN_PASSWORD`.

## Переменные окружения (.env)

| Переменная | Описание | По умолчанию |
|------------|----------|--------------|
| `NEXTCLOUD_PORT` | Порт веб-интерфейса на хосте | 18082 |
| `NEXTCLOUD_ADMIN_USER` | Логин администратора | admin |
| `NEXTCLOUD_ADMIN_PASSWORD` | Пароль администратора | **обязательно задать** |
| `NEXTCLOUD_TRUSTED_DOMAINS` | Доверенные домены/хосты (через пробел) | localhost 127.0.0.1 |
| `NEXTCLOUD_DB_PASSWORD` | Пароль БД Nextcloud | nextcloud |
| `NEXTCLOUD_DB_ROOT_PASSWORD` | root-пароль MariaDB | nextcloud_root |

**Важно:** задайте `NEXTCLOUD_ADMIN_PASSWORD` и при необходимости смените `NEXTCLOUD_DB_PASSWORD` / `NEXTCLOUD_DB_ROOT_PASSWORD` перед первым запуском.

## Доступ извне (веб и приложения)

Чтобы заходить с других устройств и из интернета (как в Google Drive / Яндекс.Диск):

1. **Доверенные домены**  
   В `.env` укажите все адреса, по которым будете открывать Nextcloud (через пробел):
   ```env
   NEXTCLOUD_TRUSTED_DOMAINS=localhost 127.0.0.1 192.168.1.10 cloud.mydomain.com
   ```
   Подставьте IP вашего сервера в LAN и/или домен, если есть.

2. **Доступ по IP в локальной сети**  
   - Порт 18082 проброшен на хост. С другого устройства в той же сети: `http://IP_СЕРВЕРА:18082`.  
   - Добавьте этот IP в `NEXTCLOUD_TRUSTED_DOMAINS` (например `192.168.1.10`).

3. **Доступ из интернета (рекомендации)**  
   - Вынести Nextcloud за **обратный прокси** (Caddy, Nginx, Traefik) с **HTTPS** и задать в `NEXTCLOUD_TRUSTED_DOMAINS` ваш домен (например `cloud.mydomain.com`).  
   - В настройках Nextcloud (или через `overwrite.cli.url`) указать базовый URL: `https://cloud.mydomain.com`.  
   - Мобильные приложения и десктоп-клиент подключаются к этому URL.

4. **Мобильные приложения**  
   - **Nextcloud** в App Store / Google Play.  
   - В приложении укажите адрес сервера: `http://IP:18082` (LAN) или `https://cloud.mydomain.com` (если настроен HTTPS).  
   - Логин и пароль — учётная запись пользователя Nextcloud.

5. **Синхронизация на ПК (Nextcloud Desktop)**  
   - https://nextcloud.com/install/#install-clients  
   - Укажите URL сервера и учётные данные. Папки будут синхронизироваться как с Google Drive.

## Данные и бэкапы

- **Файлы:** том Docker `nextcloud_data` (каталог внутри контейнера `/var/www/html`).  
- **БД:** том `nextcloud_db_data`.  
- Рекомендуется настроить периодический бэкап этих томов (или соответствующих каталогов на хосте, если используете bind mount) и при необходимости — бэкап конфигурации Nextcloud из веб-интерфейса (Настройки → Администрирование → Бэкапы / резервное копирование).

## Альтернативы

Если нужен более лёгкий вариант только с веб-файловым менеджером без полного «облака»:

- **FileBrowser** — один образ, веб-UI, базовый шаринг.  
- **Filestash** — веб-клиент к существующему хранилищу (S3, SFTP, WebDAV и т.д.).

Для сценария «как Google Drive / Яндекс.Диск» с вебом, приложениями и синхронизацией Nextcloud остаётся основным вариантом в плане.
