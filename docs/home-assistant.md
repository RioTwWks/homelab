# Управление умным домом (Home Assistant)

Moltbot по голосовым командам вызывает Home Assistant API: свет, выключатели, климат (температура). Сначала обрабатываются медиа-команды, затем — команды умного дома.

## Настройка

1. **Поднять Home Assistant** (если ещё не поднят):
   ```bash
   docker compose --profile ha up -d
   ```
   HA будет на `http://localhost:8123` (порт 8123 проброшен с контейнера; при проблемах с доступом ранее использовался `network_mode: host`, но на части систем порт не открывался — оставлен bridge).

2. **Создать Long-Lived Access Token** в Home Assistant:
   - Зайти в веб-интерфейс HA → профиль (иконка внизу слева) → внизу страницы блок «Токены».
   - «Создать токен», ввести имя (например `moltbot`), скопировать токен.

3. **Прописать в `.env`** (в корне репо):
   ```env
   HOME_ASSISTANT_URL=http://host.docker.internal:8123
   HOME_ASSISTANT_TOKEN=ваш_долгоживущий_токен
   ```
   Если HA и moltbot-api в одном Docker Compose, укажите `http://homeassistant:8123`. Если moltbot-api в Docker, а HA на хосте — `http://host.docker.internal:8123`.

4. Перезапустить **moltbot-api**:
   ```bash
   docker compose up -d moltbot-api
   ```

## Какие команды распознаются

Распознавание по ключевым словам (без LLM), маппинг в сервисы HA.

| Фразы (примеры) | Действие | Домен HA |
|-----------------|----------|----------|
| Включи свет, включи свет в гостиной, свет выключи | Вкл/выкл | `light` |
| Выключи свет в кухне | Выкл по комнате | `light` |
| Температура 22, поставь 22 градуса, установи температуру 21 | Установка температуры | `climate` |

- **Комнаты:** гостиная, кухня, комната, спальня, ванная, кабинет, коридор, прихожая, балкон, детская и т.д. Подбор entity по `entity_id` и `friendly_name` из HA (регистр не важен).
- Без указания комнаты команда «выключи свет» применяется ко **всем** сущностям домена (все светильники). Чтобы управлять одной комнатой — говорите «включи свет в гостиной».

## Подключение устройств в HA

Интеграции Zigbee/Matter/MQTT/Wi‑Fi настраиваются в самом Home Assistant (Настройки → Устройства и службы). После появления устройств они получают `entity_id` (например `light.living_room`, `climate.thermostat`). Moltbot использует тот же API: получает список состояний, фильтрует по домену и по ключевым словам комнаты в названии/entity_id, вызывает сервис.

## Проверка

```bash
curl -s http://localhost:18080/v1/chat \
  -H 'content-type: application/json' \
  -d '{"text":"включи свет в гостиной","session_id":"test"}' | jq -r .reply_text
```

Ожидаемый ответ при успехе: «Включила.» При отсутствии устройства с «гостиная» в названии — сообщение об ошибке.

## Переменные окружения

| Переменная | Описание |
|------------|----------|
| `HOME_ASSISTANT_URL` | Базовый URL HA без слэша (например `http://host.docker.internal:8123`) |
| `HOME_ASSISTANT_TOKEN` | Long-Lived Access Token из профиля HA |

Если одна из переменных не задана, голосовые команды умного дома не выполняются (остальные интенты работают как раньше).
